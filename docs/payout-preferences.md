# Payout preference setup — 2026-09-23

Players can open Home → Cash out → Add payout method and save a PayPal email or a US Venmo username. They re-enter the identifier and confirm ownership; Venmo also requires US-account confirmation. Saved summaries mask the identifier; Edit reveals it to the authenticated owner, and Remove deletes the current preference. No password, bank detail, API credential, OAuth connection or provider verification is collected.

`web/payout.mjs` handles the form and Firestore service. `payoutPreferences/{Firebase UID}` stores only `method`, `destination`, `usResident`, `version: 1`, and server `updatedAt`. It is separate from profiles, game records, rewards and corpus exports. Browser reads/removals are owner-only, collection listing is denied, and create/update requires current participation/consent. Shape/format rules reject extra verification/payment/balance fields. Current authorized Firebase admins can inspect preferences for future payment operations.

The application loads from the server and acknowledges saves only when the Firestore write resolves. Errors keep the form unconfirmed. Account reset clears in-memory identifiers and suppresses delayed responses. The preference can change: a future withdrawal must snapshot and reconfirm the destination, run identity/fraud checks, reserve real cash balance, and store an immutable payment record with provider reference/idempotency before sending. Never treat a stored string as proof of account ownership, valid provider eligibility or an instruction to send money.

This is user setup only. UMI's issuing account is not needed to store preferences. No payout is requested or sent; cash balance remains $0, current pilot points remain nonredeemable, and saved details are labeled unverified. Manual or automated payments still require a separately authorized and reconciled payment workflow. Do not copy identifiers into Git, analytics, training manifests or general logs.

Validation includes controller cases for malformed/mismatched entries, unsuccessful loads/saves, duplicate clicks, successful save/remove and late callbacks after sign-out; Firestore emulator cases cover owner isolation, current consent, forbidden privileged fields, format checks and removal after withdrawal. Mobile layout and synthetic saved state were reviewed at 390×844. No real payment or live participant payout detail was used in testing.
